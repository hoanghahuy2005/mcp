Liste des types¶

Chaque élément de ProjeQtOr peut être typé à votre convenance selon votre métier ou votre domaine d’activité.

Chaque type est présenté de la même manière. Une section de description très simple, avec différents champs selon l’élément, et une section comportement qui conditionnera vos actions futures selon les paramètres saisis.

Section comportement¶

Cette section est commune à plusieurs types d’éléments.

Permet de déterminer certains comportements de l’interface, selon les types d’éléments.

Description ou Commentaires

Case cochée indique que le champ Description est obligatoire.

Responsable

Case cochée indique que le champ Responsable est obligatoire lorsque le statut de traitement de l’élément est « En cours ».

Résultat

Case cochée indique que le champ Résultat est obligatoire lorsque le statut de traitement de l’élément est « Terminé ».

Indicateur de statut

Vous pouvez verrouiller le macro-statut : En cours - Terminé - Clos - Annulé

Ces champs permettent de déterminer si les cases à cocher concernées sont verrouillées ou non.

Si la case est cochée, vous ne pourrez modifier le macro-statut qu’à l’aide des statuts du workflow.

Pas de travail restant sur Terminé

  • Les éléments planifiables ne peuvent pas passer au statut Terminé s’il reste encore du travail.

Projet¶

Projet directeur

La définition est faite par le type de projet, vous définissez que certains types de projets ne peuvent pas avoir d’activités, uniquement des sous-projets ou des jalons.

Traduction¶

Type de demande de traduction

Statut initial des éléments

L’état initial des lignes correspond à l’état de la demande qui entraînera la génération automatique des lignes de traduction selon les langues enregistrées sur votre version de produit ou de composant.

Délai de traduction (nb jours)

Le délai de traduction (en jours) détermine l’échéance pour la date de livraison planifiée qui sera calculée automatiquement à partir de la création de la demande. Cette période est exprimée en durée calendaire et ne tient pas compte des jours non ouvrés.

Type d’élément de traduction

Statut de génération de l’élément

Correspond à l’état dans lequel les lignes seront créées.

Restrictions des types¶

Permet de limiter les valeurs affichées dans la liste de valeurs pour chaque type d’élément.

Les restrictions peuvent être définies pour un projet, un type de projet ou un profil.

Note

Section restrictions des types sur l’écran Projet

Pour afficher la section restrictions des types : Allez dans Paramètre global > Onglet Activité > Section Contrôles et Restrictions « autoriser la restriction de type sur le projet » doit être défini sur « Oui ». Possibilité de définir davantage de restrictions pour un projet par rapport aux restrictions définies au niveau du type de projet.

Gestion des restrictions de type

  • Cliquez sur le bouton Restreindre les types pour afficher la boîte de dialogue.

  • Pour chaque type d’élément, sélectionnez les valeurs qui figureront dans la liste des valeurs affichées.

  • Par défaut, si aucun type d’élément n’est sélectionné, toutes les valeurs de la ligne seront affichées sur chaque écran concerné.

Affiche les noms des types d’éléments où une restriction est appliquée

Rappel : Cela signifie aussi, aucune restriction pour les types d’éléments restants sur chaque écran dédié.

OPE : Projet opérationnel¶

Dans ProjeQtOr, les projets opérationnels peuvent être associés à un type de facturation.

Cette association permet aux documents financiers (factures, devis, bons de commande, etc.) d’être automatiquement adaptés à la méthode de facturation spécifique au type de projet concerné.

En fonction du type de facturation défini, des raccourcis spécifiques apparaîtront dans les documents financiers.

Ces raccourcis facilitent la récupération automatique des données pertinentes (temps passé, dépenses, coûts, etc.) liées au projet, optimisant ainsi le suivi financier.

ADM : Projet administratif¶

Type de projet pour suivre le travail non productif : congés, maladie, formation, …

Tous les nouveaux types sont créés avec le code ADM.

Chaque ressource pourra saisir du travail réel sur ces projets, sans avoir à être allouée au projet, ni affectée aux activités du projet.

Les affectations à toutes les tâches du projet seront automatiquement créées pour que les utilisateurs puissent saisir du travail réel.

Ces projets ne sont pas visibles sur les écrans de type Gantt.

Certaines sections et champs ne sont pas visibles ou ne fonctionnent pas sur les projets administratifs comme Suspendu, Planification fixe ou le seuil minimum.

TMP : Projet modèle¶

Ces projets ne seront pas utilisés pour suivre un travail.

Ils sont conçus uniquement pour définir des modèles, à copier en tant que projets opérationnels.

Tout chef de projet (profil) peut copier ces projets, sans avoir à y être alloué.

Tous les nouveaux types sont créés avec le code TMP.

PRP : Projet de proposition¶

Ces projets ne seront pas utilisés pour suivre un travail.

Ce type de projet permet de définir si un projet est stratégiquement intéressant à réaliser.

Tous les nouveaux types sont créés avec le code PRP.
