Fonctions¶

La fonction définit la compétence générique d’une ressource qui peut être liée à un coût.

Les coûts saisis ici ne seront pas pris en compte directement dans le tableau des fonctions de l’écran des ressources.

Ce sont des coûts proposés par défaut mais qui peuvent être modifiés lors de la création de la fonction sur l’écran des ressources.

Pour modifier les fonctions et les coûts sur l’écran des ressources, vous devez passer par la fonction de mise à jour du coût des ressources.

Coût interne et externe

Vous pouvez définir deux coûts par fonction, un interne (existant) et un externe (nouveau).

Lors de la définition du coût d’une ressource, le coût par défaut proposé doit dépendre du fait que la ressource est externe ou interne :

Si « est externalisé » est coché pour la ressource, le coût externe sera attribué. Sinon, ce sera le coût interne

Mettre à jour le coût des ressources

Vous pouvez répercuter les coûts actuels à toutes les ressources à partir du coût de la fonction en tenant compte du critère externe ou interne de la ressource.

Cliquez sur le bouton Mettre à jour les coûts des ressources

Vous avez 3 options pour effectuer ce traitement. Cela déterminera comment les affectations et les coûts d’activité seront mis à jour.

Ajouter un nouveau coût à partir de la date

Cette option vous permet de créer un nouveau coût pour les ressources dont la valeur commence à la date saisie.

  • Le coût des activités affectées reste inchangé.

  • Le coût réel des activités tient compte du nouveau coût à partir de la date que vous avez saisie

  • Le coût restant des activités prend le nouveau coût.

Remplacer le coût existant

Cette option vous permet de simplement remplacer le coût actuel de la ressource (le dernier coût si ce montant a varié dans le temps)

  • Le coût des activités affectées reste inchangé

  • Le coût réel des activités tient compte du nouveau coût

  • Le coût restant des activités prend le nouveau coût

Remplacer le coût d’affectation initial

Cette option vous permet de remplacer le coût actuel de la ressource (le dernier coût si ce montant a varié dans le temps) tout en forçant le coût d’affectation initial (pour les affectations non clôturées) à ce nouveau coût.

  • Le coût des activités affectées prend le nouveau coût

  • Le coût réel des activités prend le nouveau coût

  • Le coût restant des activités prend le nouveau coût

Note

Afin de conserver le fonctionnement initial de la solution, lors de la migration, le coût externe sera initialisé avec la même valeur que le coût interne.

De même, lors de la saisie du coût interne, le coût externe sera initialisé à la même valeur s’il est vide. Afin de permettre la saisie d’un coût externe à zéro, cela ne sera fait que lors de la saisie sur l’écran (pas de mise à jour systématique côté serveur).

Statut¶

Le statut est un élément important du cycle de vie des éléments.

Il définit l’avancement du traitement de l’élément.

Certaines automatisations sont implémentées, selon la définition du statut, à appliquer sur les éléments.

Voir aussi

Workflow.

Statut Affecté

Ce statut indique que vous avez affecté une ressource à une activité.

Cela peut déclencher le changement de statut automatique lorsque vous affectez une ressource pour la première fois sur un élément planifiable de ProjeQtOr si le paramètre global est activé.

Si l’affectation est déjà présente ou si vous utilisez l’affectation automatique de l’équipe projet, le changement de statut ne sera pas effectif

Statut En cours

Ce statut précise que le traitement de l’élément est pris en charge.

Un responsable peut être déterminé ou requis.

Statut Suspendu

Cet état indique que le traitement de l’élément est dans un état suspendu.

Utilisé pour le traitement de certains éléments (activité, tickets…).

Vous permet d’exclure et de purger le calcul du planning.

L’enregistrement de ces temps de pause vous permet d’obtenir des informations de traitement plus précises.

Remettre l’activité sur un projet non suspendu doit alors la désuspendre : ceci est valable si la suspension provenait de l’héritage du projet.

Statut Terminé

Ce statut précise que le traitement de l’élément est terminé.

Un résultat peut être spécifié ou requis.

Il est possible d’exiger un résultat lorsque le statut passe à « terminé ».

Statut Clos

Ce statut indique que l’élément est clos.

Cet article est archivé et n’apparaîtra plus dans les listes.

Vous pouvez afficher ces éléments en cochant l’option « clos » en haut à droite de l’écran

Statut Annulé

Ce statut précise que l’élément est annulé.

Consolidation des changements de statut

Nous avons un paramètre qui permet de définir automatiquement le statut de l’élément parent.

Il dépend du statut des éléments enfants et des statuts disponibles dans le workflow.

Note

Sélectionnez OUI définir automatiquement le statut de l’activité parent dans les paramètres globaux pour l’utiliser.

  • Si une activité passe au statut « En cours », tous les parents passent au premier statut « En cours » disponible dans le workflow.

  • Si une activité passe à un statut « terminé », « clos » ou « annulé », chaque parent passe au premier statut « terminé » ou « clos » selon le statut de tous ses enfants.

Avertissement

Si le statut des éléments parents n’a pas été modifié automatiquement, vérifiez vos contrôles comme les champs obligatoires.

Vous pouvez déterminer un nombre de cartes et une valeur pour chacune d’elles.

Chaque valeur est associée à un nombre de jours de charge.

Cette charge sera reportée après le vote sur l’élément utilisé pour la user story (ticket, exigence, activité)

Urgences¶

L’urgence du ticket est un élément fourni par le demandeur pour indiquer la rapidité de traitement nécessaire pour le ticket.

Champs obligatoires ¶

Champ

Description

Id

Identifiant unique pour cette valeur.

Nom

Nom de cette valeur.

Valeur

Valeur de l’urgence.

Couleur

Couleur pour afficher l’urgence dans les listes d’éléments.

Ordre de tri

Numéro définissant l’ordre d’affichage dans les listes.

Clos

Indicateur pour signaler que cette valeur est archivée.
