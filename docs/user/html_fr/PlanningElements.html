Éléments de planification¶

ProjeQtOr fournit tous les éléments nécessaires à la construction d’une planification à partir de la charge de travail, des contraintes entre les tâches et de la disponibilité des ressources.

Les éléments de planification Sessions de test et Pilotage sont décrits dans leurs rubriques respectives.

Projet¶

Le projet est l’entité principale de ProjeQtOr.

Il constitue également le niveau supérieur de visibilité, selon les Profils.

Un tableau de bord de projet est disponible pour suivre les informations clés.

Voir aussi

Tableau de bord des projets

Sous-projets¶

  • Vous pouvez définir des sous-projets sur n’importe quel projet, et ce de manière illimitée.

  • Dans l’écran du projet parent, vous pouvez visualiser les projets enfants dans la section des sous-projets.

  • Ainsi, les projets peuvent ne pas être de véritables projets, mais simplement une décomposition organisationnelle correspondant à une structure.

Type de projet¶

Il existe 4 types de projets qui ne sont pas gérés de la même manière.

OPE : Projet opérationnel¶

Projet à suivre. Celui sur lequel vous travaillez.

Tous les nouveaux projets sont créés avec le code par défaut OPE.

Les projets opérationnels sont liés aux types de facturation.

Voir aussi

types de projet

ADM : Projet administratif¶

Type de projet pour suivre le travail non productif : congés, maladie, formation, …

Toutes les ressources pourront saisir du travail réel sur ces projets, sans avoir à être affectées au projet ni assignées aux activités du projet.

Des Assignations à toutes les tâches du projet seront automatiquement créées pour permettre aux utilisateurs de saisir du travail réel.

Ces projets ne sont pas visibles dans les écrans de type Gantt.

Certaines sections et certains champs ne sont pas visibles ou ne fonctionnent pas sur les projets administratifs, comme Suspendu, Planification fixe ou le seuil minimum.

TMP : Projet modèle¶

Ces projets ne seront pas utilisés pour suivre du travail.

Ils sont simplement conçus pour définir des modèles, destinés à être copiés en tant que projets opérationnels.

Tout chef de projet (Profil) peut copier ces projets, sans avoir à y être affecté.

PRP : Projet de proposition¶

Ces projets ne seront pas utilisés pour suivre du travail.

Ce type de projet permet de définir si un projet est stratégiquement intéressant à réaliser.

Voir aussi

type de projet

Traitement du projet¶

Planification fixe

Lorsque la case « planification fixe » est cochée, la planification du projet ne sera pas recalculée.

  • Cela évite de modifier les valeurs prévues.

  • La planification restera toujours identique, quelles que soient les actions effectuées sur d’autres projets.

Avertissement

Cela peut entraîner des incohérences dans les dépendances.

Projet non extensible

Lorsque le périmètre du projet est fixé, vous ne pouvez pas :

  • ajouter de nouveaux éléments à ce projet

  • supprimer des éléments de ce projet

  • déplacer des éléments vers ou depuis ce projet

En construction

Lorsqu’un projet est en construction, aucun e-mail automatique ne sera envoyé, aucune notification ni alerte ne sera générée pour les éléments du projet.

  • Un projet peut être en construction tant qu’il n’est pas déclaré. Défini avec le statut En cours.

  • Les ressources ne le voient pas dans les Imputations.

Exclure du plan global

  • Ne pas afficher les éléments non planifiables de ce projet dans la vue de planification globale.

  • Cela signifie que seuls les éléments de planification standard seront affichés, à l’exclusion de :

  • Actions

  • Décisions

  • Livraisons

Traitement du travail validé

Active le traitement du travail validé sur la base de la somme du travail des ordres de projet ; sinon, il sera calculé sur la somme du travail validé des activités.

Indicateurs manuels

  • Les champs : État de santé, Niveau de qualité, Tendance et Avancement global sont des indicateurs manuels.

  • Ils permettent de définir de manière visuelle l’état général, la conformité, la tendance et l’avancement du projet.

  • Certains indicateurs manuels sont affichés dans l’écran Aujourd’hui.

Champs spéciaux

  • La valeur des champs Nom du projet, Commanditaire, Code projet et Code contrat peut être utilisée comme valeur de substitution des champs spéciaux.

  • Voir : Champs spéciaux

Indicateur de suivi

  • Les indicateurs peuvent être définis dans les données d’avancement.

Ne pas démarrer le projet avant la Date de début validée

  • La planification ne doit démarrer qu’à partir de cette date, comme s’il existait un Jalon fixe précédant le projet.

  • Les ressources ne peuvent pas imputer de travail sur le projet avant la date spécifiée (comme pour un projet en construction).

  • Cette option doit être activée dans les paramètres globaux.

Réserve du projet¶

La réserve du projet est un montant réservé sur la base de l’identification des Risques et des Opportunités.

Elle est calculée à partir de la réserve pour aléas des risques, diminuée du gain potentiel des opportunités.

ProjeQtOr utilise une technique dite de « Valeur monétaire attendue (VME) » pour convertir les risques et les opportunités en montant.

Le montant de la réserve du projet sera ajouté au montant restant.

Abaque¶

La fonctionnalité Abaque est actuellement disponible dans une version initiale (V0).

Dans cette version :

  • aucun calcul automatique n’est appliqué

  • les valeurs ne sont pas automatiquement utilisées dans les estimations

  • elles servent actuellement uniquement de référence informative

Les Abaques doivent donc être utilisés :

  • comme aide à la décision

  • comme outil de capitalisation des connaissances et des expériences

  • comme cadre de référence pour les estimations

Les informations peuvent être consultées et appliquées manuellement par les chefs de projet.

Note

Les évolutions futures pourront permettre :

  • l’utilisation automatique dans les estimations

  • l’intégration dans les calculs de planification

  • l’exploitation dans les Rapports.

Voir aussi

Activité¶

Une activité est un type de tâche qui doit être planifiée, ou qui regroupe d’autres activités.

Les activités peuvent être :

  • Tâches de développement.

  • Tâche d’initialisation ou de conception.

  • Tâche de test.

  • Tâches récurrentes de maintenance ou de support.

  • Phases qui contiendront des sous-tâches.

  • Toutes les tâches planifiées.

Les ressources sont assignées aux activités. Lors d’une assignation, un certain travail est initialement planifié sur cette activité pour la ressource.

Pour une ressource, les activités assignées sont les tâches dans lesquelles elle peut saisir le Travail réel

Activités parentes¶

  • Les activités peuvent avoir des parents pour regrouper des activités ou des tâches planifiées.

  • Les activités peuvent être triées à l’intérieur de leur activité parente, dans la vue de planification Gantt, par glisser-déposer dans la zone de liste.

  • L’activité parente doit appartenir au même projet.

  • Lorsqu’une activité parente contient une assignation avec une charge de travail, le mode de planification appliqué ne correspond à aucun de ceux proposés dans la liste des modes de planification.

  • Sur une activité parente, le mode de planification n’est plus affiché.

Planification de l’Activité¶

  • Les Tickets peuvent être liés à une activité (tâche).

  • Le travail sur les Tickets sera inclus dans l’activité.

Assignation des ressources à la tâche

  • Les ressources qui travailleront sur le Ticket n’ont pas besoin d’être assignées préalablement à l’activité liée.

  • L’assignation sera automatiquement créée dès que cette ressource aura saisi le temps de travail (travail réel) dans le Ticket.

  • La tâche assignée et la somme des saisies de temps de travail par ressource dans les Tickets seront disponibles dans ses Imputations.

Traitement¶

Planification fixe

  • Lorsque la case « planification fixe » est cochée, la planification de l’activité ne sera pas recalculée.

  • Cela évitera toute modification des valeurs planifiées.

  • La planification restera toujours identique, quelles que soient les actions effectuées sur d’autres projets.

Avertissement

Cela peut entraîner des incohérences dans les dépendances.

Filtre sur la liste

Possibilité de filtrer les activités par données ou par type, par exemple par ressources assignées

Indicateur de suivi

  • Les indicateurs peuvent être définis dans la Liste des valeurs.

  • Voir : État de santé et Avancement global

Session de test¶

Cet élément de planification est une activité spécialisée destinée aux tests.

Une session de test permet de définir un ensemble de cas de test devant être exécutés pour satisfaire une Exigence.

Elle peut regrouper d’autres sessions de test ou constituer une tâche. Cela permet de définir la structure des sessions de test.

Les dates, travaux et coûts des sessions de test (enfants) sont récapitulés dans la session de test (parent).

Une tâche est assignée à des ressources pour être réalisée.

Voir aussi

Sessions de test

Jalon¶

Other sections

  • Avancement

  • Prédécesseur et Successeur

Un Jalon est un repère dans la planification, destiné à mettre en évidence les dates clés.

Les Jalons sont couramment utilisés pour contrôler les dates de livraison.

Ils peuvent également être utilisés pour mettre en évidence la transition d’une phase à la suivante.

ProjeQtOr propose deux types de Jalons :

Jalon flottant

  • Ce Jalon se déplacera automatiquement pour tenir compte des dépendances.

Jalon fixe

  • Ce Jalon est fixe dans la planification et ne tient pas compte des dépendances avec les prédécesseurs.

  • Ce type de Jalon est utile, par exemple, pour définir la date de début de certaines tâches.

  • La date fixe est définie par la date validée.

Indicateur de suivi

  • Les indicateurs peuvent être définis dans la Liste des valeurs.

  • Voir : État de santé et Avancement global

Section Détails

Les éléments liés au Jalon (Jalon cible) sont affichés dans le tableau.

  • Contient la liste des versions de produit.

  • Contient la liste des Exigences.

  • Contient la liste des Tickets.

  • Contient la liste des Activités.

Dépendance¶

Les dépendances permettent de définir l’ordre d’exécution des tâches (séquentiel ou concurrent).

Tous les éléments de planification peuvent être reliés à d’autres par des dépendances.

Il existe plusieurs types de dépendances permettant de démarrer et/ou de terminer avant/après un autre élément.

Les dépendances peuvent être gérées dans le diagramme de Gantt et dans l’écran de l’élément de planification.

Un délai peut être défini entre le prédécesseur et le successeur.

Plusieurs types sont disponibles :

  • Début à Début : la seconde activité ne peut démarrer que lorsque la première activité a démarré.

  • Fin à Début : la première activité doit être terminée avant que la seconde activité puisse commencer.

  • Fin à Fin : la première activité doit être terminée avant que la seconde puisse être achevée.

En tout état de cause, le successeur peut se terminer avant le prédécesseur. Notez que le successeur « ne devrait » pas se terminer après la fin du prédécesseur, mais dans certains cas cela ne sera pas respecté :

  • si la ressource est déjà utilisée à 100 % jusqu’à la fin du successeur

  • si le successeur possède un autre prédécesseur de type « Fin-Début » ou « Début-Début » et que le temps restant est insuffisant pour terminer la tâche

  • si le délai à partir de la date de début de planification ne permet pas d’achever la tâche.

Voir aussi

Dépendances

Réunion¶

Cet élément de planification se comporte comme un Jalon fixe, mais c’est une tâche.

Comme un Jalon, une réunion peut constituer un point de transition.

Mais aussi comme une tâche, car il est possible d’y assigner des ressources et du travail planifié.
